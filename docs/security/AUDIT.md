## 2. Что исправлено в этом PR

1. **Открытый редирект после входа по ссылке из письма** (`src/app/auth/callback/route.ts`).
   Адрес вида `/auth/callback?next=/\evil.com` уводил человека на чужой сайт после подтверждения почты: удобная схема для фишинга.
   Теперь принимаются только адреса внутри сайта.
2. **Перерасход ключа ИИ** (`src/lib/rate-limit.ts`). Любой зарегистрированный пользователь мог скриптом отправлять запросы к ИИ без ограничений и исчерпать квоту для всех.
   Добавлены лимиты: разговор — 150 ответов в час на человека, голос — 300 запросов в час, личный план — 10 в час, демо — 30 в час с адреса.
   Адрес посетителя в демо теперь берётся из заголовка, который ставит Vercel, а не из подделываемого `X-Forwarded-For`.
3. **Заголовки безопасности** (`next.config.ts`): запрет встраивания в чужие сайты (защита от clickjacking), HSTS, `nosniff`, `Referrer-Policy`, микрофон только для самого сайта, убран заголовок `X-Powered-By`.
4. **Текст ошибки базы не уходит пользователю** в `/api/chat`, проверяется формат идентификатора разговора.
5. **Уязвимость postcss** (GHSA-qx2v-qp2m-jg93 и др.): обновлён до 8.5.29 через `overrides` в `package.json`. `npm audit --omit=dev` — 0 уязвимостей.
6. **Согласие на обработку персональных данных**:
   - при регистрации две обязательные галочки: согласие на обработку и трансграничную передачу данных; подтверждение 18+ и принятие условий. Проверка на сервере, не только в браузере;
   - согласие сохраняется с датой, версией и языком в профиле пользователя Supabase (Authentication → Users → `user_metadata.consent`): это доказательство на случай проверки;
   - пользователи, зарегистрированные раньше, при следующем входе видят экран согласия; без него разделы и API недоступны, можно отказаться и выйти;
   - при изменении политики достаточно поменять `CONSENT_VERSION` в `src/lib/consent.ts`, и все подтвердят заново.
7. **Политика конфиденциальности и условия использования** на трёх языках: `/privacy`, `/terms`. Ссылки на главной, при регистрации, в профиле и в демо.
   В демо под полем ввода: «Это ИИ, а не специалист… не пишите имя и адрес».
8. **Миграция `0004_security_hardening.sql` (ещё не применена к базе)**: политики таблицы личного плана приведены к тому же виду, что у остальных таблиц, у гостей отозваны права на таблицы с личными данными. Применяется только после вашего согласия.

### Желательно

- Проверка пароля сложнее «8 символов» (Supabase → Authentication → Password requirements).
- Ограничение частоты в памяти сервера — мягкое: на Vercel несколько экземпляров считают по отдельности. Для жёсткого лимита нужен общий счётчик (Upstash Redis или таблица в Supabase).
- Полная политика `Content-Security-Policy` для скриптов (сейчас только запрет встраивания и форм на чужие адреса).
- Журнал согласий в отдельной таблице (сейчас в `user_metadata`, его технически может перезаписать сам пользователь через API; для доказательства у аудитора лучше таблица, куда пишет только сервер).
- `npm audit` для инструментов разработки: `braces` в `eslint-config-next` — на сайт не попадает.
- Предупреждение советника про `delete_own_account` — осознанное решение: функция удаляет только аккаунт вызывающего (`auth.uid()`), без неё не работает «Удалить аккаунт».
- Резервные копии: на бесплатном тарифе Supabase нет управляемых бэкапов с восстановлением на момент времени.
- Регламент на случай утечки: кто и в какой срок уведомляет уполномоченный орган и пользователей.

## 4. Юридическая часть (Казахстан)

> Это не юридическое заключение. Список составлен по открытым источникам, чтобы сэкономить время юриста, а не заменить его. Перед запуском на широкую аудиторию покажите юристу этот раздел и тексты `/privacy` и `/terms`.

### 4.1. Согласие и прозрачность — закрыто этим PR
Закон РК «О персональных данных и их защите» требует согласия субъекта на сбор и обработку, в том числе в электронной форме, и информирования о целях. Сделано: обязательные галочки, тексты политики и условий, сохранение факта согласия, возможность отозвать (удалить аккаунт).

### 4.2. Хранение данных за пределами Казахстана — главный риск
- В законе РК есть требование хранить персональные данные граждан в базе, находящейся на территории Казахстана (норма о локализации). Сейчас база Supabase находится во Франкфурте (Германия), хостинг Vercel — там же, ИИ Google — в том числе в США.
- Трансграничная передача разрешена в страны с надлежащей защитой или с согласием человека — согласие мы теперь берём. Но согласие на передачу, по распространённому толкованию, не снимает требование хранить основную копию в РК.
- Варианты, которые стоит обсудить с юристом:
  1. оставить как есть на этапе пилота, с явным согласием на трансграничную передачу (уже сделано), и заложить переезд;
  2. перенести базу на хостинг в Казахстане (например, PostgreSQL у казахстанского облачного провайдера) и оставить за рубежом только обработку ИИ;
  3. хранить в РК основную копию, а за рубежом — только то, что нужно для ответа ИИ в моменте.

### 4.3. Чувствительные данные
Разговоры касаются эмоционального состояния и могут содержать сведения о здоровье. Это повышает требования к защите и к выбору поставщика ИИ (см. п. 1 раздела 3). Сервис не оказывает медицинских услуг: это прямо сказано в условиях, в профиле и в демо.

### 4.4. Несовершеннолетние
Сейчас сервис ограничен 18+ (галочка при регистрации). Причины: условия Google Gemini API запрещают сервисы для людей младше 18, а для обработки данных несовершеннолетних закон требует согласия законного представителя. Если планируется молодёжная аудитория младше 18 — нужен другой поставщик ИИ и механизм согласия родителей. Это решение влияет на маркетинг (см. `ideas/opora-kazakhstan.md`).

### 4.5. Закон РК «Об искусственном интеллекте»
Закон № 230-VIII от 17 ноября 2025, действует с 18 января 2026. Требует прозрачности ИИ-систем. Пользователь должен понимать, что общается с ИИ: это указано при регистрации, в демо, в профиле и в условиях. Подробные требования к маркировке и к ответственности уточнить у юриста.

### 4.6. Уведомление об утечках
Оператор обязан уведомлять уполномоченный орган об утечках персональных данных в короткий срок (по практике крупных операторов — в течение одного рабочего дня). Это обещано в политике; нужен внутренний регламент, кто это делает.

## 5. Как повторить проверку
```bash
npm audit --omit=dev            # уязвимости в зависимостях сайта
npm run lint && npx tsc --noEmit
curl -sI https://<домен>/ | grep -iE "strict|frame|nosniff|referrer|permissions|content-security"
```
В Supabase: Advisors → Security; SQL `select * from pg_policies where schemaname = 'public';`.
