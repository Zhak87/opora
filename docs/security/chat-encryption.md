# Замок на разговоры с ИИ

Текст разговоров с ИИ-собеседником (сообщения, выводы «в дневник», названия разговоров из первой реплики)
хранится в базе зашифрованным: `enc1.<iv>.<шифр>`. Ни база, ни её резервные копии, ни админка, ни Supabase
Studio текста не показывают.

## Как устроено

- Шифр AES-256-GCM, у каждого человека свой ключ: HKDF-SHA256 от главного ключа `CHAT_ENCRYPTION_KEY` и id человека.
  Id ещё и «доп. данные» шифра, так что строку одного человека нельзя подложить другому.
- `CHAT_ENCRYPTION_KEY` создаёт выкладка на сервере один раз (`/opt/opora/server.env`), в GitHub, базе и
  ночных копиях базы его нет. Код: `src/lib/vault.ts`.
- Шифрует и расшифровывает только сервер сайта: чат (`/api/chat`), история (`src/lib/history-actions.ts`,
  она же отдаёт историю приложению через `/api/mobile/action`), план, курс, «Пять шагов», материалы для психолога
  (только с согласием клиента: `client_ai_material` отдаёт шифр, сайт открывает его ключом клиента).
- Старые строки без `enc1.` читаются как есть. Перешифровать их: Actions → Server → `encrypt-chats-check`
  (только счёт), потом `encrypt-chats`. Повторный запуск ничего не меняет.

## Что важно знать

- ИИ (Gemini) должен видеть текст, чтобы ответить: сервер открывает его на время ответа. Это не
  «сквозное» шифрование, а шифрование хранения: прочитать базу без ключа с сервера нельзя.
- Потеря `CHAT_ENCRYPTION_KEY` = потеря всех разговоров. Сохраните копию ключа офлайн (например, на флешке
  в надёжном месте): `grep CHAT_ENCRYPTION_KEY /opt/opora/server.env` по SSH. Менять ключ нельзя без перешифровки.
- Ночные копии базы, сделанные до перешифровки, ещё содержат открытый текст и удаляются сами через 14 дней.
- Метрики собеседника (`meta.route`: фокус, фаза, оценка) остаются открытыми кодами для `/admin/companion`.
