# 14. Политика доступа сотрудников к сервису и данным

> Внутренний документ. Черновик. Роли в коде: `public.admins.role` = `viewer` | `admin` | `developer` (миграция 0015), действия админов пишутся в `audit_log`.

## 1. Принцип

Каждый получает минимальный доступ, нужный для его работы, и только после подписи обязательства о конфиденциальности (документ 17). Доступ выдаёт владелец; список доступов ведёт ответственный (документ 11).

## 2. Роли

| Роль | Кто | Что может | Что не может |
| --- | --- | --- | --- |
| `viewer` | SMM, аналитик, партнёр | смотреть обезличенную статистику в `/admin` | менять что-либо, видеть почты пользователей **[проверить, что не видит]** |
| `admin` | модератор, менеджер психологов | проверять анкеты психологов (видит документы об образовании), блокировать пользователей, разбирать жалобы | выдавать роли, доступ к серверу |
| `developer` | владелец, ведущий разработчик | всё в панели, выдача ролей | — |
| Сервер (SSH, `server.env`) | только владелец и ведущий разработчик | выкладка, резервные копии, ключи | — |
| GitHub (репозитории) | разработчики | код; секреты GitHub — только владелец | — |
| Google AI Studio, Resend, hoster.kz, домен | только владелец | оплата, ключи | — |

Психолог — не сотрудник: его доступ определяется согласием клиента (документы 02, 03).

## 3. Что никто не делает

- Не читает тексты разговоров, дневника, расшифровок, переписки клиента с психологом. Тексты разговоров с ИИ зашифрованы; расшифровывать их вручную разрешено только по запросу самого пользователя (например, восстановить историю) или по законному требованию госоргана, с записью в журнал.
- Не выгружает базу и данные на личные устройства, в облака, мессенджеры.
- Не использует реальные данные пользователей для тестов и демонстраций; для этого есть тестовые аккаунты.
- Не передаёт свои пароли и не входит под чужим аккаунтом.

## 4. Обязательные меры

- Двухфакторный вход: GitHub, Google (AI Studio, почта), hoster.kz, Resend, регистратор домена, Apple/Google аккаунты разработчика.
- Отдельный аккаунт в «Опоре» для работы с админкой, не личный с личной историей **[рекомендация]**.
- Пароли — в менеджере паролей (Bitwarden, 1Password), не в заметках и чатах.

## 5. Выдача и отзыв доступа

1. Запрос → владелец решает → человек подписывает документ 17 → роль выдаётся в `/admin/users` → запись в таблицу доступов.
2. При уходе человека из проекта в тот же день: снять роль, удалить из GitHub, сменить общие пароли и ключи, к которым у него был доступ.
3. Раз в 6 месяцев — пересмотр: у кого какой доступ и нужен ли он ещё.
